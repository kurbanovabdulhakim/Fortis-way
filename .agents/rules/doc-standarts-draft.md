# AI-First Documentation Standards (`resume`)

> **Purpose:** Strict directives for any AI agent (Antigravity, Cursor, Hermes, Codex) creating or maintaining Markdown files, specifications, templates, or reports in `c:\Users\Abdulkhakim\gitHub\resume`.

---

## 1. Mandatory YAML Frontmatter Schema

Every `.md` document in the repository (root, `docs/`, `.agents/`, `db/`, `scripts/`) **must** begin with standard YAML frontmatter:

```yaml
---
title: English Title (primary key for AI routing)
description: One-line concise English summary of purpose
status: active | pending | done | future | draft
category: runbook | architecture | model | plan | spec | reference | security | rule | index
tags: [tag1, tag2, tag3]
last-verified: YYYY-MM-DD
summary-ru: Краткое описание на русском для пользователя (1-2 строки)
summary-uz: Foydalanuvchi uchun o'zbek tilidagi qisqacha tavsif (1-2 qator)
related:
  - path/to/related-file.md
---
```

### Field Definitions:
- **`title`**: In English. Used by agents as an indexing and disambiguation key.
- **`description`**: Single-line plain text summary (no markdown/HTML).
- **`status`**: Current operational status (`active`, `pending`, `draft`, `future`).
- **`category`**: Document archetype for classification.
- **`last-verified`**: Date (`YYYY-MM-DD`) when contents were last checked against code/DB.
- **`summary-ru` / `summary-uz`**: Human operator summaries in Russian and Uzbek.
- **`related`**: Explicit list of relative paths to related files to preserve mental graph for LLMs.

## 2. Special Rules for Template & Context Files

### A. Template Files (`cover_letters/` & `variants/`)
- Templates must contain HTML comment blocks describing available substitution variables:
  ```markdown
  <!--
    Template: Banking & Finance Cover Letter
    Placeholders:
      {{company}}            - Target employer name
      {{position}}           - Job title
      {{sector_hook}}        - Opening paragraph tailored to sector
      {{key_achievement}}    - Metric-driven achievement
      {{salary_expectation}} - Target salary
      {{candidate_name}}     - Abdulkhakim Kurbanov
      {{date}}               - Generation date
  -->
  ```
- Placeholders must strictly use the double-bracket format: `{{variable_name}}`.

### B. Machine-Generated State Files (`AI_CONTEXT.md` & `PIPELINE.md`)
- `AI_CONTEXT.md` and `PIPELINE.md` are dynamically generated by `scripts/dashboard.py`.
- They must retain the required YAML frontmatter generated programmatically on each export.
- Agents must **not** edit these two files by hand; always regenerate them via `python scripts/dashboard.py`.

## 3. Language Conventions

| Section | Language | Rationale |
|---------|----------|-----------|
| Architecture, plans, rules, code docs | **English** | Universal tokenization, maximum LLM precision |
| Candidate Resume (`master/resume.md`) | **Russian** (with EN variants if added) | Primary hiring language in Tashkent / Uzbekistan |
| Cover Letters (`cover_letters/`) | **Russian** / **Uzbek** / **English** | Aligns with job vacancy language requirements |
| Metadata summaries (`summary-ru`, `summary-uz`) | **Russian / Uzbek** | Immediate readability for repository owner |

---

## 4. No Orphan Files & Link Integrity

1. **Master Indexes:**
   - Any new architectural documentation, runbook, or specification must be indexed in both `README.md` and `AGENTS.md`.
2. **File References:**
   - Always reference files by their canonical relative path from repository root (e.g., `db/schema.sql`, `scripts/config.py`).
   - For user-facing links in responses, use markdown links with forward slashes.

---

## 5. Zero Stale Documentation Rule

- If a CLI parameter changes in `scripts/`, update `scripts/README.md` and `AGENTS.md` in the same commit.
- If the SQLite schema in `db/schema.sql` changes, update `db/schema.md` immediately.
- Never close a task while leaving contradictory documentation in the workspace.
